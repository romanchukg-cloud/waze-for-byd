# Waze for BYD 5.22.90.123 — test.4

An experimental update with automatic failure diagnostics, a Support screen and
a gated DiLink 5.1 HUD transport. Physical testing of these additions is pending.

## Changes

- **Automatic diagnostics:** a default-selected first-use choice, with transmission
  starting after Continue and verification of server support. Only measured source,
  adapter and projection failures trigger reports. No successful-session uploads
  or inferred full-app crashes/ANRs.
- At most one new automatic report per installation per 24 hours, a persistent
  cooldown, one automatic slot in the three-report queue and bounded expiry.
  Turning the option off stops automatic retries, removes unsent reports and
  requests cancellation of known queued reports. Manual reports stay independent.
- **Settings > Support · Waze for BYD:** manual Preview/Send, separate cluster/HUD/
  stock-navigation observations, status, validated GitHub issue links, cancellation,
  60-second structured-event capture and sanitized JSON export.
- Reports use the existing HTTPS diagnostics service. Automatic schema-v2 requests
  are explicitly marked and capability-gated; the server groups matching failures
  by project/build/failure/UTC day into a canonical issue. Manual v1 remains available.
- Strict structured recording, limited to 1 MiB/ten minutes and 256 KiB/500 events
  per report. No routes, coordinates, road names, accounts, raw logs, exception
  messages, screenshots or persistent hardware IDs. A limited technical summary
  may appear in this repository's **public GitHub Issues**. Opt-out is in Support.
- **Experimental DiLink 5.1 / Android 13 HUD path:** explicit clusterdebug receiver,
  start/guidance/end packets, BYD turn codes, street text, one-second keepalive and
  pending-clear recovery. Enabled only for the exact known firmware, receiver
  version and signing certificate. Other configurations retain AMap output.
- Steering-wheel zoom remains research only.

## Validation

- Android 12L/API32 and Android 13/API33: **120 diagnostics checks on each**, using
  a separate test APK with fake delivery and no INTERNET permission. Covers notice,
  opt-out, actual event hooks, successful-session exclusion, cooldown/clock guards,
  queue capacity, capability fallback, original request replay, cancellation,
  expiry, manual sending, preview and SAF export. No public test issues created.
- 33 shared-server tests passed locally with fake delivery, plus Waze-specific
  concurrent submissions and lost-reply recovery linked to one canonical fake issue.
- Actual Java-generated Waze automatic v2 JSON accepted by the shared server
  validator locally. Live HTTPS capabilities confirm v2 and automatic grouping;
  this is not evidence of real Waze issue delivery.
- 60 guidance and 200 standalone-HUD checks, plus Android Intent action/component/
  flags/extra-type checks, without broadcasts to a car.
- Signature, 16 KiB alignment and ZIP integrity verified. Compared with test.3,
  only classes11.dex, manifest and signature entries differ. Original resources,
  native libraries and DEX 5/6 remain identical to test.3.
- Same com.waze package, versionCode 1030811 and existing signing certificate.
  Initialized emulator test.3 → test.4 install-r retained UID, firstInstallTime,
  private data sentinel and opt-out. The updated notice kept the checkbox off;
  Continue saved notice version 2. Real account preservation has not been tested.
- Support opened in the final Waze APK on Android 12L. Native Settings access on
  the Google-free emulator is still subject to upstream location onboarding.

## Remaining validation

Real Waze diagnostic delivery, BYD Settings/document-provider availability,
OEM background restrictions, reboot and force-stop behavior need device tests.
Reports already being delivered/published cannot be recalled. If an automatic POST
response was lost, opt-out clears local content without resending POST; the server
may still deliver that previously accepted report.

The new DiLink 5.1 transport still needs receiver identity, normal-app-UID dispatch
and visible arrow/distance/street/end checks on the specified car. Successful
broadcast dispatch does not prove physical output. Earlier parked Android 12
observations apply to the earlier build, not a physical test of test.4.

Shared server source, credentials and internal handoffs remain local-only. This
release changes Waze client code, build tooling, tests and public documentation.
See [diagnostics](../diagnostics.md) and [DiLink 5.1 HUD](../dilink-5.1-hud.md).
