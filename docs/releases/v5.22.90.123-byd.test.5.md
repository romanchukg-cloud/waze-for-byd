# Waze for BYD 5.22.90.123 — test.5

An experimental update with a cluster map layout for DiLink 5.1 / Android 13.
It is built for testers with a DiLink 5.1 car and is not yet validated on one.

## Changes

- **DiLink 5.1 cluster map layout**, based on measurements by DiPlay's maintainer:
  - **Map theme:** the full-width `shared_fission_bg_XDJAScreenProjection_0` layer.
    Waze draws a 1920×480 map at y 144, between the speed/status and gear/range
    readouts, with a light or dark backdrop and DiPlay's contrast fades.
  - **Scenario and Simple themes:** the right side card (x 1320, 600×720) on
    `shared_fission_bg_XDJAScreenProjection_1`. Everything else stays transparent.
  - **Displays:** only exactly named 1920×720 displays are used. A missing side layer
    is never replaced with the full layer.
- **Settings → Support · Waze for BYD → Cluster map layout**:
  - **Layout profile:** Automatic (DiLink 5.1 only on verified firmware), DiLink 5.1
    on any firmware, or DiLink 5.
  - **Cluster theme:** Scenario (default), Map, Simple, or **Follow the cluster
    automatically**. Follow mode reads stock cluster activities through Usage Access.
  - **Map theme background:** theme default, light or dark.
  - **Local status:** display list, chosen layer and viewport, Waze surface size,
    Usage Access, and every DiLink 5.1 HUD gate check. It is never uploaded.
- **Usage Access** is declared and must be granted by the owner once:
  `adb shell appops set com.waze GET_USAGE_STATS allow`.
  Without it, the fixed theme still works.
- **No stale map on the cluster:** hidden layers stay transparent until a replacement
  is shown. After a crash or force-stop, unused 5.1 layers are cleared on the next start.
- **No change on DiLink 5:** on other firmware, Automatic keeps the test.4 cluster map.
  HUD packets, AMap guidance and diagnostics behave as in test.4.

## For testers on DiLink 5.1

1. Install as an update with the same signing certificate. Do not uninstall or clear data.
2. Open Waze → Settings → **Support · Waze for BYD**.
3. Check **Cluster layout** in the status. On another 5.1 build it says DiLink 5;
   then select **DiLink 5.1 layout, also on unverified firmware**.
4. Select the theme your cluster shows: Map, Scenario or Simple. Optionally grant
   Usage Access and select **Follow the cluster automatically**.
5. Report with photos of the cluster and a screenshot of the Support status. Note
   whether the map fits the card or strip, whether it covers stock readouts, and
   whether it disappears when the card or theme changes. If the HUD shows nothing
   during a route, the HUD lines of the status are needed too.

## Validation

- **Signing and packaging:** signature, 16 KiB alignment and ZIP integrity verified.
  Compared with test.4, only `classes11.dex`, the manifest and signature entries differ.
  The only manifest change is the `PACKAGE_USAGE_STATS` declaration. Same `com.waze`,
  versionCode 1030811 and signing certificate.
- **Android 13 emulator (API 33)**, with the three 1920×720 320 dpi cluster layers of
  the reference car:
  - Waze surfaces of 600×720 on `_1` and 1920×480 on `_0`.
  - Captured pixels confirmed transparency outside the card, the Map backdrop and
    fades, and cleared layers after theme changes and after a force-stop.
  - Follow mode worked with stub activities that use the stock package and class names.
  - The DiLink 5 profile kept the previous full-display surface.
- **Tests:** 39 cluster layout/state checks, 60 guidance and 200 HUD checks, Android
  intent checks and 120 diagnostics checks on API 33.
- **Update:** test.4 → test.5 with `install -r` on an initialized emulator kept the
  UID, firstInstallTime, a private data sentinel and the diagnostics choice.

## Remaining validation

None of the DiLink 5.1 behaviour is verified on a physical car:
- map content and position;
- legibility of the stock readouts;
- stock activity events;
- layer clearing on the vehicle compositor;
- the 5.1 HUD.

The emulator's Waze drew no map tiles. The HUD remains gated to the exact known
firmware and receiver.
