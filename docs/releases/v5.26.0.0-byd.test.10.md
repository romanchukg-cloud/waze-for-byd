# Waze for BYD 5.26.0.0 — test.10

An experimental update with steering-wheel zoom for the cluster map and a diagnostic
that records Waze's lane data. It also includes the zoom fix from the unreleased test.9.

## Changes

- **Cluster zoom works (test.9).** Waze 5.26 turns a run of scale events into one pinch,
  so the single event sent before never changed the zoom. The Zoom out and Zoom in
  buttons now send a short run of steps, about 2x for each press.
- **Steering-wheel zoom.** Off by default. The custom button switches zoom mode on and
  off. In zoom mode volume + and - zoom the cluster map. Outside zoom mode, during a
  call and while no cluster map is shown, the keys keep their normal actions. See
  [Steering-wheel zoom](../wheel-zoom-research.md).
  - The panel can assign other wheel buttons and shows the keys it receives.
  - Keys arrive through a key-only accessibility service, which BYD lets you enable only
    over ADB, or through the focused Waze window.
- **Lane diagnostic.** Waze records the lanes its engine reports and the lane image it
  draws in `Android/data/com.waze/files/lanes`. There are no road names or positions.
  **Lanes are not sent to the HUD yet**, and nothing new is sent to the car.
- **Build.** The build adds one XML entry to Waze's resource table for the service's
  metadata. All other resources are unchanged, and `aapt2` checks the result.
- **Cluster start.** The enabled service keeps the Waze process running, so the cluster
  map then waits until a Waze window has been opened.

## Validation

- **Reference DiLink 5.0 car:**
  - installed as an update that kept the UID and app data;
  - Waze started without a crash and the cluster map appeared;
  - the new panel section appeared with the default buttons;
  - the key service connected after it was enabled over ADB, and other services were kept;
  - after the car was switched off and on, the service stayed listed but was not
    connected, even after Waze was opened. Running the setup command again reconnected it;
  - Waze did not start by itself after the car was switched on;
  - the owner confirmed that the panel's zoom buttons change the cluster zoom (test.9);
  - on a test.9 drive, the cluster camera followed the car and guidance was sent.
- **Android 13 emulator:**
  - ART verification passed;
  - the button's day colours matched Waze's own buttons;
  - on that heavily loaded host Waze repeatedly showed "not responding" during start,
    with none of this project's code in the traces. It did not happen on the car.
- **JVM:** 61 guidance, 207 HUD, 65 cluster layout and theme, and 43 wheel key checks.

## Remaining validation

**Not yet confirmed:**

- physical wheel buttons: whether the custom and volume buttons reach Waze and zoom
  the cluster, with or without the service. So far only one other key from the same input
  device has been seen, and it reached both the service and the Waze window;
- whether the camera keeps following the car after a zoom;
- the lane diagnostic on real data, and collecting its folder with `adb pull`;
- DiLink 3 and DiLink 5.1.

**Open questions:**

- **Stopped camera.** The owner saw the cluster camera stop following the car once on
  test.8. It did not happen again, and the cause is unknown.
- **Crash at the end of the Go now countdown.** It was seen on the emulator in the
  ETA overview of a resumed drive and has not been checked in a car.
